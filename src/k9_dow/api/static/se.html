Systems engineering · future plan

The same engine, applied to engineering reviews.

Building a complex system means passing a series of engineering checkpoints, the technical reviews. At each one, engineers show a review board that the design is ready for the next step, against a checklist, with a set of documents to prepare. DAS does this for acquisition decisions; the SE pipeline would do it for the technical reviews: AI agents prepare and check the review documents, and an engineer decides at every review.

Planned, not yet built. This page describes a future plan. What exists today is DAS and the first technical review it already runs (the System Requirements Review); everything else here is marked Planned.

  • Design model (SysML v2) or design documents
  • Interface descriptions
  • Previous review decisions and baselines

The usual sequence. The current set, names and entry criteria are to be confirmed with a systems engineering expert against DoDI 5000.88 (Engineering of Defense Systems) and the DoD Systems Engineering Guidebook before anything is built.

Agents

Four DAS squads already do engineering work and carry over; four new roles and one new integration complete it.

TraceabilityIN DAS

Every requirement traced to design and test; links proposed and validated; orphans found; coverage scored.

Change detectionIN DAS

What changed since the last approved baseline, and whether it matters.

Review readinessIN DAS

Readiness for each review scored against its entry criteria, with the gaps listed.

Architecture viewsIN DAS

System views generated and checked for consistency with each other.

Requirements decomposerPLANNED

Splits system requirements into functional and subsystem requirements.

Interface analystPLANNED

Lists the interfaces between parts and checks that each side agrees.

Verification plannerPLANNED

Proposes how each requirement will be tested, inspected or analyzed.

Review package builderPLANNED

Assembles the package for each review from the outputs above.

Model link (SysML v2)PLANNED

An integration adapter to read and write the engineers' design models through the SysML v2 API, so agents work on the model, not only documents.

How it would run

The same shape as DAS: each approved review starts the next. A router sends the event to one orchestrator, which runs the review's squads; each squad runs its agents in order; the package goes to a review board in K9X HIL, whose decision starts the next review. Each layer knows only the one below it.

SRR approved (DAS)→Router→ Technical Review Orchestrator→squads → agents→ review board in K9X HIL→next review

How it works with DAS

A separate solution on K9-AIF, so DAS stays stable; on this site for users, with the same login, programs, jobs and K9X HIL review queues. The two exchange work by events where they meet. DAS does not have to be finished first: the SE pipeline needs only an approved requirements baseline, which DAS already produces at the SRR, or an existing approved requirements document.

Scope

  • A future plan. Only the SRR and the reused DAS squads exist today.
  • The reviews and their criteria are to be confirmed by a systems engineering expert against current DoD guidance.
  • People decide at every review. The pipeline prepares and checks; it does not replace engineering judgement.
  • Agents built with other frameworks (CrewAI, LangGraph, Claude Agent SDK) can run inside K9-AIF, governed at the boundary.
